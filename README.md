# WinZoom

**任意のウインドウだけを拡大表示するツール** — Per-window magnifier for Windows

「ウインドウサイズを変更できない」「サイズを変えても中身が再配置されず余白が増えるだけ」といった古い業務アプリなどを、**そのアプリだけ** 125〜400% に拡大して普段どおりに操作できるようにします。

画面全体を拡大する拡大鏡とは違い、指定したウインドウだけが大きくなり、ほかのアプリはそのままです。

![WinZoom](docs/icon.png)

## 特徴

- **入力が自然に届く**
  - クリック、ドラッグ、ホイール、右クリックメニュー、範囲選択、キー入力がそのまま使えます。
  - メッセージを偽装して送るのではなく、本物のマウス入力を元ウインドウの正しい位置に届けます。
- **カーソルの動きが自然**
  - 拡大表示の上でも、マウスはいつもの速さと加速感で動きます。
  - 拡大領域から出入りしても継ぎ目がありません。
- **ポップアップも一緒に拡大**
  - メニュー、ドロップダウン、ツールチップ、所有ダイアログもまとめて拡大します。
- **他のウインドウと正しく重なる**
  - 他アプリが手前に来れば拡大表示も隠れ、クリックはそのアプリに届きます。
- **最大化ウインドウも拡大できる（擬似最大化）**
  - 最大化中のウインドウで `Ctrl+Alt+Z` を押すと、拡大した状態で画面いっぱいに表示します。
  - 解除すると、元の通常サイズを書き戻してから最大化に戻します。
- **移動・リサイズに追従**
  - タイトルバーで移動でき、拡大表示の縁からリサイズもできます。
  - 最小化中は自動で一時停止し、元に戻すと再開します。
- **はみ出し調整**
  - 拡大後に画面からはみ出す場合はウインドウを自動で移動し、解除時に元の位置へ戻します。
- **倍率をアプリごとに記憶**
  - 一度設定した倍率は exe ごとに保存されます。
- **アプリ側に手を加えない**
  - DLL 注入や描画フックは使いません。対象アプリのファイルやプロセスは変更しません。

## 動作環境

- Windows 10 (1809 以降) / Windows 11、x64
- インストール不要です。`WinZoom.exe` を実行するとタスクトレイに常駐します。

## 使い方

1. `WinZoom.exe` を起動します（タスクトレイに虫めがねのアイコンが出ます）。
2. 拡大したいウインドウを前面にして `Ctrl+Alt+Z` を押します。
3. もう一度 `Ctrl+Alt+Z` を押すと解除します。

| 操作 | 内容 |
|---|---|
| `Ctrl+Alt+Z` | 前面のウインドウを拡大 / 解除 |
| `Ctrl+Alt+＋` / `Ctrl+Alt+－` | 倍率を上げる / 下げる（テンキーの＋－も可） |
| 拡大表示の上で `Ctrl+Alt+ホイール` | 倍率を変更 |
| トレイアイコンをクリック | メニュー（拡大 / 解除、倍率選択、使い方、終了） |

倍率は 125 / 150 / 175 / 200 / 225 / 250 / 300 / 350 / 400% から選べます。画面に収まらない倍率は、収まる最大値に自動で抑えます。

### 最大化ウインドウの拡大（擬似最大化）

最大化中のウインドウに `Ctrl+Alt+Z` を使うと、次の手順を自動で行います。

1. 最大化状態と、通常時の位置・サイズを保存します。
2. 最大化を解除し、ウインドウを「作業領域 ÷ 倍率」のサイズにして画面左上に置きます。
   - 例：作業領域が 1920×1040 で倍率 200% なら、ウインドウは 960×520 になります。
   - アプリはこのサイズに合わせて中身を再配置し、それを 2 倍に拡大するので、ちょうど画面いっぱいになります。
3. 倍率を変えると、ウインドウのサイズも自動で合わせ直します。
4. 解除すると、保存した通常時の位置・サイズを書き戻してから最大化します。

擬似最大化の途中で最大化ボタンを押すと、拡大を解除して普通の最大化に戻ります。

### 設定ファイル

`%LOCALAPPDATA%\WinZoom\WinZoom.ini` に保存されます。

```ini
[General]
DefaultScale=1.50

[Scale]
legacyapp.exe=2.00
```

## 仕組み

WinZoom はアプリの描画を乗っ取らず、**元ウインドウの上に拡大表示を重ねる** 方式です。

1. **表示**
   - DWM サムネイル API を使い、元ウインドウの合成済み画面を GPU で拡大します。
   - 拡大した画面は、クリックを透過するオーバーレイウインドウに表示します。
   - 画面キャプチャを使わないので、描画の遅延はほぼありません。
2. **マウス**
   - 低レベルマウスフックでマウスの移動量を 1/倍率 にします。
   - これにより、**本物のカーソル** を元ウインドウ上の対応する位置に置きます。
   - オーバーレイはクリックを透過するので、クリックやドラッグは本物の入力として元ウインドウに届きます。
   - 本物のカーソルは非表示にし、見た目のカーソルを拡大側の位置に描きます。
3. **キーボード**
   - フォーカスは元ウインドウに残したままなので、そのまま届きます。
4. **追従**
   - WinEvent フックで、元ウインドウや関連ポップアップの表示・移動・Z オーダー変化を監視します。

## 既知の制限

- **擬似最大化の開始・解除時の切り替わり**
  - 開始時と解除時に、ウインドウのサイズが切り替わる様子が一瞬見えます。
- **擬似最大化中にアプリを閉じた場合**
  - ウインドウサイズを記憶するアプリは、小さいサイズ（作業領域 ÷ 倍率）を記憶することがあります。
  - 先に `Ctrl+Alt+Z` で解除してから閉じてください。
- **最小サイズが決まっているアプリ**
  - 「作業領域 ÷ 倍率」より小さくできないアプリは、画面に収まる倍率に自動で抑えます。

- **管理者権限で動くアプリ**
  - WinZoom も管理者として起動しないと、操作が届かない場合があります。
- **ちらつき**
  - メニューやドロップダウンが開く瞬間、元サイズのものが一瞬見えることがあります。
- **IME の候補ウインドウ**
  - 元サイズの位置に表示されます。
- **ドラッグ＆ドロップの持ち込み**
  - 拡大表示の外から中へのドラッグ＆ドロップには対応していません。
- **絶対座標の入力**
  - リモートデスクトップ越しの操作や、ペン・タッチ入力では位置が合いません。
- **画質**
  - 拡大はビットマップの拡大なので、文字は多少ぼやけます。
- **同時に拡大できる数**
  - 拡大できるウインドウは同時に 1 つだけです。

> GDI で描画しているアプリであれば、exe のプロパティ →「互換性」→「高 DPI 設定の変更」→「システム (拡張)」でもくっきり拡大できる場合があります。WinZoom は、それで効かないアプリに向いています。

## ビルド方法

- Visual Studio 2026（「C++ によるデスクトップ開発」ワークロード）
- Windows SDK 10.0

`WinZoom.slnx` を開き、**Release / x64** でビルドします。出力先は `bin\x64\Release\WinZoom.exe` です。

コマンドラインでビルドする場合:

```bat
msbuild WinZoom.vcxproj /p:Configuration=Release /p:Platform=x64
```

Visual Studio 2022 でビルドする場合は `/p:PlatformToolset=v143` を付けてください。

GitHub Actions でも自動ビルドします。`v*` のタグを push すると、Release に zip が添付されます。
